Hooks follow the Open Plugins hooks specification and live in a plugin's hooks/hooks.json, discovered from <project>/.agents/plugins/<name>/ or ~/.agents/plugins/<name>/; a hook-only plugin needs no manifest. Each command runs under sh -c with a JSON payload on stdin naming the event under `event`. Only PreToolUse and Stop can block: exit 2 (reason from stderr) or {"decision":"block","reason":...} on stdout; exit 0 with empty stdout allows. A hook failure (spawn error, timeout, undecodable or unrecognised output) is logged and the call proceeds unless the PreToolUse action sets on_failure: block; Stop stays fail-open even then. No field to modify a tool call and no ask/confirm decision is documented. |

PreToolUse and Stop are the only events that can block; a block from any other event is ignored. The verdict is the flat {decision: block, reason} body, and a bare allow is silence. No rewrite and no ask: a transform or escalate degrades to a block, never to a silent pass. Fail mode is configurable and only at PreToolUse: a failed hook is fail-open by default, and on_failure: block makes it fail closed -- agentseam's install writes on_failure: block on every hook entry it writes (goose reads it at PreToolUse only). Stop stays fail-open whatever on_failure says, and goose caps consecutive Stop blocks (GOOSE_STOP_HOOK_BLOCK_CAP). stdout is the decision channel, so a handler that prints a log line to stdout reads as no decision. The event name rides under `event`, not hook_event_name, which is what separates goose's payloads from every other adapter's. PreToolUseResult, BeforeReadFile, BeforeShellExecution and AfterShellExecution are observation-only and parse as unknown; AfterFileEdit is wired as file_changed. SubagentStart/SubagentStop are not emitted. Instruction files reach it through AGENTS.md. Evidence wanted (to test or overturn this row): https://github.com/open-coder-ai/agentseam/issues/177
