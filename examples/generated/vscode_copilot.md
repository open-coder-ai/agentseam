Two products behind one row, and they do not spell events the same way: HOOKS_BY_TARGET gives VS Code agent mode PascalCase names (Claude Code's exactly) and the GitHub Copilot CLI camelCase ones (sessionStart, userPromptSubmitted, agentStop). This adapter claimed camelCase only until 2026-08-28, so it never claimed a real VS Code payload at all -- those went to claude_code alone and were answered in its dialect, which is right at PreToolUse and wrong everywhere else. `timestamp`, which chatHookService merges into every payload, is what separates the two; Tabnine sends it too, so SessionStart -- the one event name Tabnine and VS Code share -- is left ambiguous rather than guessed. `postToolUseFailure`, previously mapped, claimed and installed for, is in neither vendor's name map: it never existed. Four response dialects, because the consumer reads a different shape at each: PreToolUse takes hookSpecificOutput.permissionDecision (ask and updatedInput both native, and updatedInput is validated against the tool's schema and silently discarded if it fails), UserPromptSubmit and PostToolUse take a top-level {decision: block, reason}, Stop and SubagentStop take those two fields nested in hookSpecificOutput and drop the block if the reason is missing, and SessionStart/SubagentStart run under ignoreErrors:true where even exit 2 is swallowed. hookEventName is echoed rather than hardcoded: _toHookResult strips hookSpecificOutput outright when the name does not match the event being run. Fails OPEN, not closed as this row claimed for two weeks: exit 2 blocks, but any other non-zero exit is a NonBlockingError that warns the user and lets the call proceed. Also parses Claude settings.json via hookClaudeCompat, and ignores `matcher` -- it is read and thrown away, so there is no tool filtering and the guard must check event.tool itself. Memory writes arrive as the 'memory' tool (create/str_replace/insert), not file edits.

## Every hook, one at a time

The story is held constant across agents so the pages compare: the same credential
heading for a memory file, the same failing test, the same prompt.

### 1. `session_start` — called `SessionStart` here

Enforcement: **detect**.

> Also claimed by **tabnine**, so `detect()` declines this payload and the agent has
> to be named: `handle(raw, handler, agent="vscode_copilot")`. Guessing between adapters
> that answer differently is worse than declining.

The agent sends:

```json
{
  "hook_event_name": "SessionStart",
  "model": "claude-sonnet-4-6",
  "session_id": "example",
  "source": "new",
  "timestamp": "2026-08-28T00:00:00.000Z"
}
```

which normalizes to:

```
event    = session_start
```

A `Decision.deny()` here produces:

_Nothing. This event is observation only, so a decision is not read._

### 3. `pre_tool` — called `PreToolUse` here

Enforcement: **best-effort**.

The agent sends:

```json
{
  "hook_event_name": "PreToolUse",
  "session_id": "example",
  "timestamp": "2026-08-28T00:00:00.000Z",
  "tool_input": {
    "command": "create",
    "file_text": "AWS_SECRET_ACCESS_KEY=EXAMPLE-PLACEHOLDER-NOT-A-KEY",
    "path": "/memories/team.md"
  },
  "tool_name": "memory",
  "tool_use_id": "example"
}
```

which normalizes to:

```
event    = pre_tool
tool     = memory
path     = /memories/team.md
content  = AWS_SECRET_ACCESS_KEY=EXAMPLE-PLACEHOLDER-NOT-A-
```

This is the gate, so every decision is worth seeing.

**`Decision.allow()`** — the handler is happy

```json
{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "allow"}}
```

Exit code: `0`

**`Decision.deny()`** — the handler refuses

```json
{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "secret detected in file content"}}
```

Exit code: `0`

**`Decision.ask()`** — the handler wants a human

```json
{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "ask", "permissionDecisionReason": "looks like a credential -- confirm?"}}
```

Exit code: `0`

**`Decision.rewrite()`** — the handler wants the input changed

```json
{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "allow", "updatedInput": {"content": "AWS_SECRET_ACCESS_KEY=<redacted>"}, "permissionDecisionReason": "redacting the secret"}}
```

Exit code: `0`
