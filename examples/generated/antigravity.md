Richest decision vocabulary here -- allow, auto_approve, deny, ask, force_ask and deny_unless_prior_grant (https://antigravity.google/docs/hooks, read 2026-10-13). PreToolUse can rewrite: its documented `overwrite` object is merged into toolCall.args (shallow, top level) before the tool runs, so a transform is {"decision": "allow", "overwrite": ...} -- a key the replacement input leaves out is kept, not removed. permissionOverrides only widens permissions and is not used. Stop's `decision: "continue"` keeps the agent going; any other value allows the stop. All of this is read from the docs, not run. The payload carries NO event name, so the event is inferred from shape, and PreToolUse/PostToolUse differ only by an `error` field documented as empty rather than absent; ties go to PreToolUse because the opposite guess would skip the gate. PreInvocation and PostInvocation have identical payloads and are unmapped. Fail mode is not documented, so the weaker claim (open) is recorded rather than a guess in our own favour. Install writes hooks.json to the docs' schema (https://antigravity.google/docs/hooks, read 2026-10-17: "The `hooks.json` file maps hook names to their event configurations"): one named hook `agentseam` whose PreToolUse/PostToolUse hold {matcher, hooks} groups (matcher "*", documented to match all tools, when none is given) and whose Stop lists its handler bare, as the docs' example lists the matcher-ignored events. Until 2026-10-17 Stop was written as a {hooks} group; a maintainer's Antigravity IDE log (2026-10-17) rejected that file, `invalid hook "agentseam": command hook must specify 'command'`, so no hook loaded. The corrected file loaded in the owner's 2026-10-18 run below. Owner witness run, 2026-10-18, chock's own Antigravity plugin (not a Claude Code plugin), Antigravity IDE on Windows 11, version not recorded (org-plan witness/results/witness-antigravity-2026-10-18.md at 16ca2e2): Antigravity named the hook jsonhook__agentseam_PreToolUse_0_0 and ran it. On Windows it runs a hook `command` through cmd.exe, so quoting inside the command does not reach git.exe: with an argument single-quoted, git split it (`unknown option: -f`) and cmd.exe ran the rest, `'{' is not recognized as an internal or external command, operable program or batch file.`; with the quotes changed to `\"`, git still failed with `unknown option: -f` (exit 129). The mechanism is inferred from that error text, not read from vendor docs or source: the `'{' is not recognized` line is cmd.exe's, and the second failure reads as Antigravity starting cmd.exe with each `"` escaped as `\"`, which git.exe takes as a literal quote, so no quoting form survives both. A command with no quotes and no space inside any argument (unquoted forward-slash paths) worked: the guard (`git commit --no-verify`) was refused at PreToolUse, the turn-end gate (an unpinned GitHub Action) was refused at Stop, and a benign `git status` ran. A hook that exited 1 halted the tool call. So a command written for Antigravity on Windows must carry no quotes and no space inside an argument. One run: no claim above changes and nothing is marked witnessed.

### 1. `pre_tool` — called `PreToolUse` here

Enforcement: **best-effort**.

The agent sends:

```json
{
  "conversationId": "example",
  "modelName": "gemini-3.6-flash-medium",
  "stepIdx": 3,
  "toolCall": {
    "args": {
      "CodeContent": "AWS_SECRET_ACCESS_KEY=EXAMPLE-PLACEHOLDER-NOT-A-KEY",
      "TargetFile": "AGENTS.md"
    },
    "name": "write_to_file"
  },
  "workspacePaths": [
    "/repo"
  ]
}
```

which normalizes to:

```
event    = pre_tool
tool     = write_to_file
path     = AGENTS.md
content  = AWS_SECRET_ACCESS_KEY=EXAMPLE-PLACEHOLDER-NOT-A-
```

This is the gate, so every decision is worth seeing.

**`Decision.allow()`** — the handler is happy

```json
{"decision": "allow"}
```

Exit code: `0`

**`Decision.deny()`** — the handler refuses

```json
{"decision": "deny", "reason": "secret detected in file content"}
```

Exit code: `0`

**`Decision.escalate()`** — the handler wants a human

```json
{"decision": "ask", "reason": "looks like a credential -- confirm?"}
```

Exit code: `0`

**`Decision.transform()`** — the handler wants the input changed

```json
{"decision": "allow", "overwrite": {"content": "AWS_SECRET_ACCESS_KEY=<redacted>"}, "reason": "redacting the secret"}
```

Exit code: `0`

**`Decision.warn()`** — the handler flags a concern

> reduced to `allow`: this agent cannot warn

```json

```

**`Decision.vouch()`** — the handler actively approves

> reduced to `allow`: this agent cannot vouch
